# Deployment

This guide publishes a public demo:

- **Backend** (Django + PostgreSQL) on [Render](https://render.com)
- **Frontend** (React) on [Vercel](https://vercel.com)

Both have free tiers. The whole process takes about 15 minutes and requires no code
changes — the repository already contains `render.yaml` and `frontend/vercel.json`.

## 1. Backend on Render

1. Push the repository to GitHub (the blueprint reads `render.yaml` from `main`).
2. In Render, choose **New → Blueprint**, connect the repository and apply.
   This creates:
   - `patri-tech-db` — PostgreSQL database
   - `patri-tech-api` — web service running `collectstatic`, `migrate` and `gunicorn`
3. Wait for the first deploy. The API should answer on
   `https://patri-tech-api.onrender.com/api/`.
4. Open the service **Shell** and create the admin user:

   ```bash
   python manage.py createsuperuser
   ```

   Optionally load the fictional dataset:

   ```bash
   python manage.py seed_demo
   ```

`DJANGO_SECRET_KEY` is generated by Render, `DJANGO_DEBUG=False`, and `DATABASE_URL` is
wired to the database automatically.

## 2. Frontend on Vercel

1. In Vercel, choose **Add New → Project** and import the same repository.
2. Set **Root Directory** to `frontend`. The framework preset is detected as
   *Create React App*.
3. Add the environment variable:

   | Name | Value |
   | --- | --- |
   | `REACT_APP_API_URL` | `https://patri-tech-api.onrender.com` |

4. Deploy. The site will be available at `https://<project>.vercel.app`.
   `frontend/vercel.json` already rewrites every route to `index.html`, so client-side
   routes such as `/dashboard` work on refresh.

## 3. Connect the two

Back in Render → `patri-tech-api` → **Environment**, set:

| Variable | Value |
| --- | --- |
| `CORS_ALLOWED_ORIGINS` | `https://<project>.vercel.app` |
| `CSRF_TRUSTED_ORIGINS` | `https://<project>.vercel.app` |

Save and redeploy the backend.

## 4. Smoke test

1. Open `https://patri-tech-api.onrender.com/docs/` — Swagger UI should render.
2. Log in on the frontend with the superuser created in step 1.
3. Create a unit, a category and an asset; edit the asset's room and confirm the history
   entry appears.

## Notes about the free tier

- Render services sleep after ~15 minutes of inactivity; the first request may take
  ~30 seconds to wake up.
- Uploaded media would be stored on the ephemeral filesystem. Configure the `AWS_*`
  variables to use S3 if media uploads are added.
- The free PostgreSQL instance is intended for demos, not for production data.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `DisallowedHost` | `DJANGO_ALLOWED_HOSTS` does not include the Render hostname (the settings add `RENDER_EXTERNAL_HOSTNAME` automatically). |
| CORS error in the browser console | `CORS_ALLOWED_ORIGINS` does not match the exact Vercel URL (scheme + host, no trailing slash). |
| `502` on the API | Check the Render build logs; usually a failing `migrate` or a missing environment variable. |
| Empty page / 404 on `/dashboard` | The Vercel rewrite is missing — confirm `frontend/vercel.json` was deployed. |
| Login fails with 400 while `/docs/` works | The request is blocked by CSRF or the API URL in the frontend points to `localhost`. |
